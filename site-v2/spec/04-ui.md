# 04 — Screen and interaction contract

## Shared interface

English, responsive layout (verify 390px and 1440px widths), PGLearn wordmark, slate text and indigo primary actions. One application shell: Learner navigation for enrolled content/certificates, Organization navigation when manager, Admin navigation for platform admin. A multi-organization manager explicitly selects an organization; show the selected name in all manager screens and export context. Scope is rechecked by server.

Use accessible HTML labels, native buttons/links, clear focus rings, inline field errors, `aria-live` save/error summaries and keyboard-operable dialogs. Skeletons while fetching, empty states with relevant next actions, and retryable errors are required. Disable only the submitting action, prevent duplicate clicks and retain input after server failure. Persisted forms show success only after acknowledgement. Never show a secret, auth action link or service key in administrative UI/logs.

Markdown authoring uses textarea + preview. Disable raw HTML and dangerous link protocols; links open with appropriate safe attributes. Do not build a rich-text editor for this release. All lists use stable pagination and named filters; table horizontal scrolling is acceptable on mobile without losing action controls.

## Learning class detail

Video player uses native controls and supplied captions. Rates 0.5,1,1.25,1.5,2 are allowed. Audio includes transcript. Text has “Mark as complete” button. Downloads show name/type/size. Primary media is not offered as a handout download, though an authorized playback URL is still copyable.

Exercise panel has instructions, a textarea labeled “Your practical response,” code-point counter up to 2,000, checkbox “I completed this practical exercise,” and “Save exercise.” Both nonblank text and confirmation required. On success show saved response read-only and completion timestamp. If media/text is incomplete, say “Exercise saved. Finish this class to complete it.” Do not label response as graded or passed.

After required class completion, next action is next incomplete class or “View certificate.” A completed program has a celebration message with explicit course completion wording, no claims of mastery. Optional classes remain accessible while entitled.

Tutor drawer exposes “Explain this” and “Give me a practical example” suggestions, question input, send action, pending indicator, validated answer and course source links. Mark examples “Illustrative example.” Show unsupported answer gracefully and provider failure with a manual retry choice. Do not block class navigation/completion while waiting for tutor. Do not auto-send again after timeout; inspect existing request state first.

A second playback tab supersedes the first. The old tab stops progress writes on SESSION_SUPERSEDED and displays “This program is playing in another tab. Resume here” to explicitly acquire a new session. Local position may continue visually, but the UI must not suggest unsaved progress is saved.

## Editor details and validation

New program creates version 1 draft. Default new module title is blank (required), class required=true, kind=video. Exercise optional until author adds it. Use explicit content inventory; do not auto-fill nine real lesson titles with invented subject matter. “AI Foundations” may appear only as a replaceable working program title.

Upload accepts the exact formats/limits in behavior spec. Complete upload then finalize; ready status only after validation. A primary upload selected for a class becomes its primary_asset_id only after successful finalize. Replacing a draft primary reference leaves the old object unreferenced for later cleanup; never overwrite a published object. Video captions/transcript must be attached before publication; validate each missing item independently.

Publish is an explicit action with a brief confirmation explaining that version content becomes read-only. This is an application user interaction, not an instruction for the coding agent to stop and ask permission during development. Publication errors preserve the draft and show field-specific issues. Preview has visible Preview badge and disables learner completion/tutor-history mutations.

## Pilot-only UI additions

CSV roster import with preview/validation and explicit apply; new draft version cloning; date update selection and audit details; certificate revocation controls; richer failed-send reconciliation. Underlying access/completion rules already apply before these convenience screens ship.
