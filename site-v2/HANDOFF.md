## Contract and default changes, with reason

**D-01 — repository layout (adapts ADR-01 and the spec/01 repository map).**
One Next.js application serves both the marketing site and PGLearn. Next forbids `app/` and `src/app/` in the same project and site-v2 already uses root `app/`, so the spec's `src/app/` is root `app/`, split into `app/(marketing)/` and `app/(platform)/`. Feature modules will go in root `features/` and `lib/` alongside the existing `components/`. Reason: one product surface, one domain, one Vercel deployment.

Route-group names in parentheses do not appear in URLs, so **every path in spec/04-ui.md resolves exactly as specified** — `/login`, `/learn/[enrollmentId]/classes/[classId]`, `/manage/[orgId]/reports`, `/admin/operations`.

**D-02 — design system (overrides ADR-16's "neutral slate with indigo actions and PGLearn text branding").**
Learner, manager and admin screens use the PG Labs `design-system-v2` tokens and components (ink/steel/brand-azure, Lora + Nunito Sans). Reason: PGLearn is a PG Labs product surface, not a separate brand, and it sits on the PG Labs domain.

Accessibility constraint carried from the token definitions: `brand-500` (#59C4ED) is only 2:1 on white and must never carry small type. Platform text on light grounds uses `brand-600`/`brand-700`; `azure-500` is the button fill with an `ink-800` label.

**D-04 — PGLearn look and feel (supersedes D-02 for `app/(platform)/` only, 8 October 2026).**
From `/login` onward, PGLearn uses the SkillSphere shadcn theme (template v1.0.0) at the product owner's request; the marketing site keeps `design-system-v2` unchanged. How it is contained:

- The theme's tokens are CSS variables (`--ui-*`, OKLCH channels) defined only under `.pglearn` in `app/globals.css`; the (platform) layout renders that wrapper. Tailwind exposes them as `ui-*` colours (`bg-ui-card`, `text-ui-muted-foreground`, …) because the design system already owns the bare shadcn names with fixed brand values.
- Platform primitives live in `components/pglearn/ui/` and keep the design system's component APIs and variant names (`primary`, `subtle`, `azure`, `coral`, …), so callers changed only their import path. `@ds/components/ui/*` is no longer imported by any platform file.
- Type is Geist (the `geist` package, self-hosted, no build-time font fetch). Raw form controls use `.pglearn-field`, text links `.pglearn-link`.
- Dark mode is per-browser via the `pglearn-theme` cookie and toggles `.dark` on the `.pglearn` wrapper, never on `<html>`, so it cannot reach marketing pages. Select popovers portal into the wrapper so they inherit the theme.
- The template is Tailwind v4; the site is Tailwind v3. Only its tokens, geometry and visual language were ported — no template code or dependencies beyond `geist` were added.

Accessibility: alerts keep their `role`/`aria-live` contract, and focus is a 3px primary ring on every control. The original SkillSphere blue (3.7:1 behind white labels) was replaced by the PG Labs tokens below.

**D-04, revised 12 October 2026 — PG Labs tokens on the SkillSphere layouts.** At the product owner's request the platform keeps SkillSphere's layouts and components but takes every token from the PG Labs design system (the "PG Labs" Design System artifact, built from the Figma frame "PG Labs — Responsible AI for Nonprofits"):

**D-05 — YouTube-hosted video for the pilot (adapts spec/03's private media and caption rules, 22 October 2026).**
At the product owner's request, the first cohort's nine videos are hosted on YouTube and embedded, so the pilot does not wait on a storage plan that accepts 1 GiB uploads. Migration M29 (`supabase/migrations/20261022000001_m29_youtube_video.sql`) adds `classes.youtube_video_id`; an uploaded file remains fully supported, and an author picks one source per class.

- **What is stored.** The eleven-character video id only, checked by a constraint; the editor reduces a pasted link to it (`lib/youtube.ts`). The learner's page renders a URL composed from that id on `www.youtube-nocookie.com`, so no caller-chosen URL or host reaches the page. The id requires `kind = 'video'` and no uploaded primary: choosing YouTube clears the primary, finalizing an uploaded primary clears the id, and leaving the video format drops it.
- **Progress is unchanged.** `components/learning/YouTubeFrame.tsx` gives `ClassPlayer` a handle with the same current time, rate and play/pause/timeupdate/ended events as a `<video>`, using YouTube's IFrame Player API (time is polled every 250 ms while playing). The intervals reach the same `record_progress` transaction and the same 90% rule; the server does not know which player sent them. Resume uses the embed's `start` parameter, so it does not autoplay.
- **Seek fix, both players.** A detected seek now closes the open interval where the seek began. Before, it closed at the new playhead, so a forward seek claimed the skipped span and the server rejected the whole beat as implausible, losing the watched part with it.
- **Publication.** A YouTube class needs its id, a duration and source text (upload the transcript, as for a file), but no uploaded primary and no caption asset: captions are YouTube's own (`cc_load_policy=1`). The duration is read from the player in the editor and can be corrected; it must match the video, because completion is 90% of it.
- **Cloning** carries the id; a primary file a class was switched away from is not copied.
- **Our controls, not YouTube's (22 October 2026).** At the product owner's request the embed asks for no YouTube control bar (`controls=0`, `fs=0`, `iv_load_policy=3`), because its logo and "Watch on YouTube" link take the learner out of the lesson. `YouTubeFrame` draws the bar instead: play/pause, back 10 seconds, a timeline with time and duration, mute and volume, captions, speed and fullscreen. **Speed is in the bar** because hiding YouTube's controls also hides its settings menu, which D-06 relied on for the rate. The bar is one 56 px row (`CONTROL_BAR_HEIGHT`), and `ClassPlayer`'s stage for a YouTube lesson reserves 16:9 plus that row, so nothing moves while it loads; on a phone, volume, back 10 seconds, the time read-out and the caption language are left out to fit. A seek on the timeline moves the playhead only, and `ClassPlayer` closes the interval where the jump began, as with the native player. **Captions** start on through the documented `cc_load_policy=1`; the on/off button and the language list use YouTube's undocumented captions module (`loadModule`/`setOption`), so every call is guarded and the button is withdrawn if they stop answering, leaving captions on. **No quality control:** YouTube retired those API calls in 2019 and chooses quality itself. **Fullscreen** puts the player and bar fullscreen together, and is not offered where the page cannot do that (iPhone Safari). **Not removed:** YouTube can still show its title or logo in some states; no parameter turns those off, and covering them is against YouTube's API terms.
- **Referrer.** Platform pages send `Referrer-Policy: same-origin`, and YouTube refuses embeds that arrive with no Referer. The iframe alone sets `strict-origin-when-cross-origin`, sending the origin and never the path, which carries enrollment and class ids.

**The cost, accepted for the pilot.** The media is as private as the YouTube video is: set each video to **Unlisted** with embedding allowed, and anyone holding the link can watch it, enrolled or not, including after a grant is revoked — AC-023 still stops progress and certificates, but not viewing on YouTube. Viewing also sends the learner's IP and the PGLearn origin to YouTube. `contracts/schema.sql` stays the v1.0 reference DDL that M01 must reproduce (`tests/unit/migration-fidelity.test.ts`); the column is M29's. `contracts/api.json` carries `youtube_video_id` on `Class`, `ClassWrite` and `ClassPatch`.

**Evidence.** `tests/unit/youtube.test.ts` (link parsing and the embed URL) and `tests/integration/youtube.test.ts` (14 tests: constraints, one source per class, publication, freeze, clone, and Amber completing a YouTube class at exactly 90% through `record_progress`). Run against PostgreSQL 17.10 with all 24 migrations and the fixture seed on stubbed Supabase `auth`/`storage` schemas, with the database clock at 2026-09-16 so the fixture offerings are open: 406 of 408 integration tests pass; the two failures are environmental (no publishable/service keys in the environment; the test runner's clock differs from the database's) and fail identically without M29. The player and editor were exercised in Chromium against a scripted stand-in for the IFrame Player API, because YouTube is not reachable from the build environment. The custom controls were exercised the same way at 1100 px and 390 px: play, a timeline seek from 0:01 to 5:00 (the beat sent closed at 1251 ms and the next interval opened at 300 s), back 10 seconds, mute, captions off and on in another language, speed 1.5×, and fullscreen in and out; inside the D-06 stage the frame is exactly 16:9 above the bar at both widths, and the bar fits one row at 390 px. **Not yet done:** playback of a real YouTube video in the deployed app, and the e2e suite, which needs Supabase Auth.

**D-11 — removing a module (adds to spec/04's version editor, 23 October 2026).**
At the product owner's request a module can be removed from a program, in two ways, from the version editor (`components/admin/RemoveModule.tsx`, after a confirmation):

- **Draft: delete.** `delete_module` (`DELETE /modules/{id}`) removes the module with its lessons, their files, exercises and source chunks — the same steps `delete_class` takes — and closes the position gap. On a published version it is refused (23514).
- **Published: hide.** A published version is frozen, so `set_module_hidden` (`PUT /modules/{id}/hidden`) hides the module instead. For every enrollment on that version it then behaves as if it were not there: it leaves the outline, its lessons are "not found" for every learning action (checked in the dispatcher with the release dates), and its required lessons stop counting in the totals, the reports and completion. Hiding settles completion for active, started, incomplete enrollments on the version, which can complete the program and issue the certificate (with its email in the outbox). Progress on the hidden module is kept; "Show module" brings it back, but never takes a completion or certificate back (spec/03: completion only moves forward).
- **Migration M32** (`supabase/migrations/20261025000001_m32_remove_module.sql`) adds `app.hidden_modules` and `app.module_listed`, and recreates the six functions that count required lessons or list the outline — `enrollment_json`, `progress_json`, `settle_completion`, `handle_get_enrollment`, `handle_get_learning_class` and `report_rows` — from their latest definitions with one listed-module filter each. `Module` gains `hidden`; task T33.
- **Not carried by cloning.** A new draft cloned from a published version contains the hidden module again (the flag belongs to the published module); delete it in the draft if it should stay out.

**Evidence.** M32 applied after M01–M31 on PostgreSQL 16 with stubbed `auth`/`storage` schemas and the fixture seed, plus an extra required module on Amber's published version. Hiding it: required total 4 → 3, the module leaves her outline, `get_learning_class` and `complete_text` on its lesson are P0002, `report_rows` agrees, and Amber, who had done every other required lesson, is completed with exactly one certificate and one certificate email queued; hiding again changes nothing. Showing it restores the total and keeps the completion. `delete_module` on a published module is 23514; on a draft it deletes the module and its lessons and renumbers the rest; an unknown module is P0002. A learner hiding is 42501; a non-boolean `hidden` is 22023. **Not yet exercised:** the integration suite and the editor against the real database.

**D-12 — the Origin check also accepts the served host (adapts spec/05, 23 October 2026).**
Moving production to `pg-learn.vercel.app` refused every sign-in (POST /login → 403 in the proxy) because `NEXT_PUBLIC_APP_URL` still named the old domain, and a `NEXT_PUBLIC_` change only takes effect after a rebuild. `lib/origin.ts` now accepts the configured origin **or** the origin the request was served on (`X-Forwarded-Host`/`Host` with `X-Forwarded-Proto`). A cross-site request carries the attacker's page as its Origin, which matches neither, so the protection is unchanged; an absent Origin is still refused. `NEXT_PUBLIC_APP_URL` is still used for links in email and should name the real domain. Evidence: `tests/unit/origin.test.ts`, and a production build with `NEXT_PUBLIC_APP_URL` set to another domain answered 200 to POST /login from its own host (direct and Vercel-forwarded) and 403 to a foreign or absent Origin.

**D-13 — test organizations follow the latest version (development aid, 23 October 2026).**

Task T34.
- **The move.** The pinned enrollment is never edited. For each active, incomplete enrollment in that organization and program not already on the latest published version, it creates the equivalent offering on the latest version (same cohort, grant and dates, shared), enrolls the person there with their start and activity dates, copies lesson progress by position (module n lesson m → module n lesson m; anything without a counterpart is dropped), settles completion on the new version, and deletes the old enrollment and everything hanging off it. Completed enrollments are skipped, so no certificate is touched. One transaction; running it again does nothing.
- **Guarded.** On an organization that is not marked as a test organization it is refused (23514): real learners keep the version they started on.

**Evidence.** M33 applied after M01–M32 on PostgreSQL 16 with stubbed `auth`/`storage`, the fixture seed and a second published version of Amber's program. Before marking: 23514.
